Claude Code 桌面版全解析：三大模式與 Skill 邏輯攻略

一句話看懂三大功能：Chat（概念對話）、Cowork（多步驟任務規劃）、Code（本地檔案實作）三位一體，通盤從靈感到落地的開發全流程。
01
Chat模式：知識諮詢中心
專注於邏輯諮詢、代碼解釋與架構規劃，不直接修改本地檔案，是開發者的靈感百寶箱。
架構討論 概念釐清 唯讀

講解重點

  • 把它當成你的資深同事：遇到不確定的設計問題，先在 Chat 裡討論。
  • 不會碰你的檔案系統，可以安心貼任何片段做解釋與 code review。
  • 適合場景：釐清需求、比較三種寫法的優劣、學一個新 API 的心智模型。
  • 可配合 Skill 擴充搜尋、數據查詢等能力（稍後在第 4 格說明）。
02
Cowork模式：自主任務代劃
具備更高的自主性，能根據規劃進行多步驟的任務協調與狀態管理。
多步驟 自主執行 狀態追蹤

講解重點

  • Cowork = AI 副駕駛：你給目標，它幫你拆任務、照順序跑。
  • 適合中等複雜度的流程：爬資料 → 分析 → 生報告；找 bug → 定位 → 驗證。
  • 與 Code 模式的差別：Cowork 偏跨工具協同，Code 偏貼著檔案改。
  • 可讓它自己決定何時呼叫 Skill 或搜尋，不用你逐步下指令。
03
Code模式：本地開發利器
直接與本地檔案系統及終端機（Terminal）對接，能撰寫、編輯代碼進行行指令，是實作的核心。
檔案讀寫 Shell 實作

講解重點

  • Code 模式 = 本地實作台，可直接建立檔案、執行測試、跑 git 指令。
  • 它跑在你的機器上，不需要雲端沙盒，速度快、權限大。
  • 最適合：寫功能、改 bug、跑 build、跟現有 repo 整合。
  • 記得用分支工作，避免直接動 main，這是 Code 模式最佳實務。
04
為什麼 Claude Chat 需要 Skill？
因為雲端對話環境是受限的「沙盒」，Skill（如搜尋、程式碼執行）是幫 AI 突破限制、外掛實時資訊的必備條件。
WebSearch CodeExec DB

講解重點

  • Chat 本身只會講話——想查資料、跑程式就必須靠 Skill。
  • 常用 Skill：網頁搜尋、程式碼執行、資料庫查詢、連接公司內部系統。
  • 把 Skill 想成雲端 Chat 的手腳，沒 Skill 只能動腦，無法動手。
  • 這也是為什麼同樣的 Claude，網頁版 vs 桌面版體驗會有落差。
05
為什麼 Claude Code 不需要 Skill？
Code 模式進行在你的本地終端，存在直接具備豐富權限與指令執行力，本地環境本身就是它最強大的實作空間。
filesystem shell zero-install

講解重點

  • 你的電腦本身就是最強的工具箱，Skill 存在的目的在本機上沒有必要。
  • 能直接用：cat、grep、git、npm、python、docker… 任何已裝的 CLI。
  • 這也代表你要謹慎授權——Code 模式有破壞力，請用 repo 隔離。
  • 建議工作流：先讓 Chat 想清楚 → 再切 Code 實作 → 出錯切回 Chat 討論。
06
進階實作技巧：想在 Code 模式使用 Skill 怎麼辦？
Route A
透過 CLI 內建工具調用（如網路搜尋）
Route B
在對話中切換為 Cowork 模式，編修更複雜的工具鏈。
小結：Chat × Cowork × Code 三者自然切換；Skill 是 Chat/Cowork 的外掛，Code 則以本地能力取代。

講解重點

  • Code 模式的 CLI 已內建常見工具，不用再掛 Skill（簡單直接）。
  • 遇到需要跨系統/流程的情境，主動切到 Cowork，讓它做任務編排。
  • 心法：Chat 想、Cowork 排、Code 做——三者分工，流程最順。
  • 最後提醒：可隨時 @ 切換模式，不要卡在一個模式硬撐。
